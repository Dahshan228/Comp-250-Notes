# Note 1: One-Day Vulnerabilities and the Patch Window

**Quotation:** “In this work, we [Fang and his coauthors] focus on studying ‘one-day vulnerabilities,’ which are vulnerabilities that have been disclosed but not patched in a system. In many real-world deployments, security patches are not deployed right away, which leaves these deployments vulnerable to these one-day vulnerabilities” (Fang et al. 2024, sec. 2.3).

**Commentary:** I think the name “one-day” is misleading.
By the authors’ definition, a flaw stays a one-day vulnerability until the patch is installed, so how long it lasts depends on the defender, not the attacker.
PHP2Shell shows this.
The PHP Foundation released a fix on October 21, 2026, but it only covered the newest versions, and many owners first had to figure out whether their products even used PHP (Ntsele 2026).
For them, the “one-day” window could have lasted weeks.
That’s why I’m using “patch window” as our main term instead.
AI doesn’t create the window, it just helps attackers use more of it, which notes 2 and 3 show.

**Subject terms:** one-day vulnerabilities; patch window; public disclosure; patch deployment
