# Note 4: Finding Flaws Before Release

**Quotation:** “We think that this work [using the Big Sleep AI agent to search code for flaws] has tremendous defensive potential. Finding vulnerabilities in software before it’s even released, means that there’s no scope for attackers to compete: the vulnerabilities are fixed before attackers even have a chance to use them” (Big Sleep Team 2024, under “Introduction”).

**Commentary:** This is the best argument I’ve found for AI helping defenders, but I think it only works in the situation the Big Sleep team describes.
The SQLite bug was in code that hadn’t been released yet, so nobody was exposed and there was no race.
PHP2Shell is the opposite.
AI found two flaws that had been in released versions of PHP for over ten years, and once the details leaked on social media, every PHP server was exposed before the PHP Foundation was ready (Ntsele 2026).
So in new code, AI fixes the problem before anyone is exposed, but in old code it starts a patch window, and note 2 shows AI is better at the attacker’s side of that window.
The “asymmetric advantage for defenders” the team hopes for (Big Sleep Team 2024) might be real, but mostly for software that hasn’t shipped yet.

**Subject terms:** vulnerability discovery; legacy code; patch window; offense–defense balance
