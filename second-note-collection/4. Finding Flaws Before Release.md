# Note 4: Finding Flaws Before Release

**Quotation:** “We think that this work [using the Big Sleep AI agent to search code for flaws] has tremendous defensive potential. Finding vulnerabilities in software before it’s even released, means that there’s no scope for attackers to compete: the vulnerabilities are fixed before attackers even have a chance to use them” (Big Sleep Team 2024, under “Introduction”).

**Commentary:** This is the best argument I’ve found for AI helping defenders, and I agree with it, but only in the situation the Big Sleep team describes.
The SQLite bug was in code that hadn’t been released yet, so nobody was exposed and there was no race.
Most code isn’t like that, though.
PHP2Shell is the opposite situation, since researchers used AI to find two flaws that had been in released versions of PHP for more than ten years.
Finding them didn’t make anyone safer right away.
It actually started a race, because every server running PHP was exposed once the details got out, and the details leaked on social media before the PHP Foundation was ready, so it had to rush its announcement (Ntsele 2026).
So I think AI finding flaws has two different effects depending on the code.
In new code, it fixes the problem before anyone is exposed.
In old code, it starts a patch window, and from note 2, AI is better at the attacker’s side of that window.
The “asymmetric advantage for defenders” the team hopes for (Big Sleep Team 2024) might be real, but I think it mostly applies to software that hasn’t shipped yet, not the huge amount of code that’s already out there.

**Subject terms:** vulnerability discovery; legacy code; patch window; offense–defense balance
